1 · Import OSM

Open uncompressed OSM XML containing nodes, ways and optionally relations. Processing stays on your computer.

Choose an OSM map to begin.

2 · Detected layers and materials

Tick to show/hide. Drag the ☰ handle to reorder; lower in this list draws on top. Choose a colour or an optional image texture per layer. Layers without matching map features show 0.

Line widths are in metres; if OSM supplies a numerical width tag it is used only when the “Use tagged widths” option is enabled.

3 · Object library

Import multiple OBJ meshes. Choose Place on a card, then click the top-down map. Each named OBJ component has its own material settings. OBJ model units are treated as metres.

No models loaded.

4 · Preview and movement

House placement: choose the object card, select Draw placement grid, drag out a rectangle from the intended corner, then use the rotation field to align. Each small square is 1 m.

In top view, adjust alignment by dragging a road or path segment sideways. Its neighbouring segments stay connected.

In Orbit: drag to rotate, Shift+drag or right-drag to pan. Select Walk using the map label, then click your starting point from overhead. Hold arrow keys for smooth movement.

Drag to pan in Top-down. In Orbit, drag to rotate and tilt. In Walk, use ↑/↓ to move and ←/→ to turn. Wheel to zoom in the top and orbit views. This WebGL preview uses real triangulated ground geometry and a perspective camera. The ground is flat; no terrain elevation is inferred.

4 · Boundary and export

Features are clipped to the file's <bounds> rectangle, or node extent if no valid bounds exist. Geometry cannot expand the map boundary. Administrative relations are treated as features, not as the clip boundary.

The JPEG is a flat overhead image suitable for map cards. SVG preserves vector paths and embedded texture images. SVG layers are in priority order; overlapping ground features are composited, not physically cut into a non-overlapping mesh.
